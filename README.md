## 1. 这是什么

一条完整的广告推荐与出价链路，对应用户给出的四个职责点：

| 职责点 | 落地位置 | 对外主张 |
|---|---|---|
| 特征与分层 | `scripts/01` `02`, `sql/*.sql` | SparkSQL 抽 192 列画像 → PCA → KMeans++ 自动分层，**ARI 0.9949** |
| 双塔预测模型 | `scripts/03` `04` `05` | DeepFM 打赢 LR/FM 基线；DFM 修延迟反馈；ZILN 估高价值用户 |
| 智能出价与水位 | `scripts/06` `08` | 拉格朗日 + PID，**B4 相对人工固定出价 +248%**，达上帝视角 **95.2%** |
| 科学实验验证 | `scripts/07` | AA 空跑 p 值服从 U(0,1)（KS p=0.115），AB 主指标 +5.45%（p=0.0013） |

**三个设计原则**（决定了代码长什么样）：

1. **Ground truth 必须可恢复。** 模拟数据不是随便 `randn` 出来的：先定义隐变量、
   二阶/三阶/四阶交叉项和 XOR 奇偶项，再生成 CTR/CVR/延迟/付费金额。只有这样，
   「DeepFM 应当打赢 FM」才是个**可验证的命题**，而不是「跑通即可」。
2. **每个模型都要有对手。** DeepFM 对 LR/FM；DFM 对 vanilla/elapsed；智能出价对
   固定出价/贪心/仅λ/仅PID。测试断言的是**相对提升**。
3. **每个数字都要有门槛，每个门槛都要能被推翻。** 门槛写在代码里、结论写进
   `problems`，非空就非零退出。

```bash
# 解释器（本机实测环境）
#   D:\miniconda3\envs\data_analysis\python.exe  (Python 3.10.16, torch 2.6.0+cpu)

python run_all.py --scale mini     # 最快的一档（数据最小、轮数最少）
python run_all.py --scale small    # 默认演示档
python run_all.py --scale full     # 10 万活跃用户，单机 CPU 上很慢

python run_all.py --scale mini --from 06    # 从第 6 步接着跑
python run_all.py --list                    # 只打印计划

# 测试（两种 runner，结果一致）

python run_tests.py
```

**为什么是 `run_all.py` 而不是 `python -m adrec`**：每个 `scripts/NN_*.py` 都能
**单独重跑**。调试某一环时不必把整条链路（生成 → 特征 → 训三个模型 → 出价 → 实验）
再跑一遍 —— 在 CPU 上那是十几分钟的事。代价是必须按顺序跑，所以 `load_*` 在产物
缺失时会抛一个**指明该先跑哪个脚本**的错误，而不是 `FileNotFoundError`。

## 4. 职责点 1 —— 特征工程与人群分层

### 4.1 数据地基（`scripts/01_generate.py`）

真值 logit 用 **Random Fourier Features** 构造：

```
f(x) = sqrt(2/D) · Σ_d a_d · cos(ω_d^T x + b_d),   ω ~ N(0, σ_ω²)
```

`σ_ω` 是**高阶交叉能量的单一旋钮** —— LR 只能拟合线性部分、FM 拟合二阶、
DNN 拟合剩余高阶。这是保证「DeepFM 显著优于 FM/LR」的**数学手段**，不是碰运气。
再叠加显式的二阶 `<z_i, v_j>`、分层×素材矩阵 `M[seg, ct]`、三阶张量
`T3[u_act, a_pop, ctx_slot]`、四阶 `T4[..., page_kind]`，以及 FM 的 rank-1 分解
**表达不了**的 XOR 奇偶项。

基率用**二分法**校准到目标值。实测（mini）：

| 指标 | 实测 | 目标 |
|---|---|---|
| CTR | **0.0500** | 0.05 |
| CVR\|click | **0.0584** | 0.06 |

**延迟反馈是刻意造出来的**，三分量混合 `0.40·δ₀ + 0.25·U(0,2h) + 0.35·LogNormal(ln36, 1.0)`：

| 归因窗口 | 6h | 24h | 72h | 168h | 线上实际标签 |
|---|---|---|---|---|---|
| 假负率 | **35.2%** | **24.5%** | **8.7%** | **2.8%** | **25.2%** |

转化延迟分位数（n = 1,168 个转化）：中位数 **0.85h**、p90 **65.2h**、p99 **239.7h**；
**50.9%** 在 1 小时内转化，超过 24 小时的是 **24.5%**。

> ⚠️ 上面那个 24.5% 和表里 24h 窗口的假负率**是同一个数，不是巧合也不是抄错**：
> 24h 窗口的假负 = 「转化延迟 > 24h 的占比」，两者按定义相等
> （`delay.frac_beyond_24h` 与 `false_negative[24h].fn_rate` 在 json 里就是同一个值）。

> 「线上实际标签」那一行比 24h 窗口的 24.5% 还高（**25.2%**），因为线上拿到的
> 不只是 24h 窗口，还有**数据末尾的截断** —— 最近那批曝光根本没等够 24 小时。

**三套标签**同时落盘：`y_conv_w24`（有偏，线上真实可得）/ `y_conv_w168`（回填，
作为现实参照）/ `label_oracle`（**仅评测，绝不进训练**）。

### 4.2 特征工程

192 列用户画像宽表，**其中 44.8% 是刻意注入的噪声与冗余**：

| 类别 | 列数 |
|---|---|
| 数值特征 | 84 |
| 类别特征 | 22 |
| **纯噪声** | **60** |
| **冗余列** | **26** |
| **合计** | **192**（噪声+冗余占比 **44.8%**）|

> ⚠️ **可观测特征必须是 latent 的含噪函数，绝不能直接放 latent**。否则模型三行
> 就学到 AUC 0.95，整个项目失去意义。泄漏检查实测：扫描 **452** 列，
> 泄漏列 **0**（`leakage.leaked_columns` 是空列表，这条由 `tests/` 断言守着）。
>
> ⚠️ **192 而不是 209**，这一处专门修过。``02_features.py`` 原先数的是
> ``profile.columns``，而 ``users`` 表被整个 copy 进画像 DataFrame，于是
> ``user_id`` / ``pay_amount`` / 13 个 ``_true_*`` 隐变量列一起被算成了"特征"——**17 列**。
> 症状是日志里那行 `画像宽表 209 列 = 类别 22 + 数值 84 + 纯噪声 60 + 冗余 26`，
> 右边加起来只有 192，**自己跟自己矛盾**；连带噪声占比的分母被撑大，
> 报成 41.1%，比真实的 44.8% 低。**一边断言隐变量没泄漏、一边把隐变量的
> 数量算进特征宽度**，是这类"数字看着挺像那么回事"的典型。现在改成数
> `build_user_profile` 声明的 ``profile_cols``，日志和本文档都对得上了。

### 4.3 PCA + KMeans++ 分层

先 `StandardScaler` 再 PCA —— 否则「曝光次数」这种量级 1e4 的列会主导主成分。
KMeans++ **在 PCA 空间**做，用轮廓系数选 K。

| 指标 | 实测 | 门槛 |
|---|---|---|
| PCA 维数 | 40 | ≤ 40 |
| 累计解释方差 | **0.8110** | ≥ 0.80 |
| 正交性误差 | **1.99e-07** | ≤ 1e-4 |
| 选中 K | **5**（真值分层数也是 5）| — |
| 轮廓系数 | **0.2034** | > 0.20 |
| **ARI vs 真值分层** | **0.9949** | > 0.85 |
| 加权纯度 | **0.998** | — |
| 最小簇占比 | **9.65%** | 无退化空簇 |

各簇画像（`cluster → 真值层`）：

| 簇 | 用户数 | 占比 | 对应真值层 | 纯度 |
|---|---|---|---|---|
| 0 | 386 | 9.65% | 4 | 1.000 |
| 1 | 1,235 | 30.88% | 0 | 0.999 |
| 2 | 577 | 14.43% | 3 | 0.998 |
| 3 | 987 | 24.68% | 1 | 1.000 |
| 4 | 815 | 20.38% | 2 | 0.993 |

**ARI 0.9949 是这一步最有说服力的数字**：无监督算法在完全不知道真值分层的情况下，
几乎完美地把它恢复了出来。

> ⚠️ **累计方差 0.811 低于「0.90」这个常见经验值**。这里如实记录，没有把门槛
> 降到实测值以下来「通过」：40 维之外的成分里本来就包含那 60 列纯噪声，
> 把它们解释掉对下游没有价值。而 ARI 0.9949 说明 40 维**足够**支撑分层。

## 5. 职责点 2 —— 双塔召回与深度排序

### 5.1 统一口径：不是两个模型，是同一个编码器的两种组合方式

| 层 | 组合方式 | 目的 |
|---|---|---|
| 召回 | 双塔**内积** `score = <h_U, h_I>/τ` | O(1) 检索，候选集 → Top-50 |
| 排序 | DeepFM **拼接 + 交叉** | 精度 |

> 候选集大小随规模档变：`full` 是 2000 个素材（对应职责描述的量级），
> 本文档所有数字采自 `mini` 档的 **400** 个（见 `04_recall.n_items`）。

> ⚠️ **跨域特征只能进排序层**。把 `user_x_category_ctr` 这类列放进 user tower，
> 双塔就失效了（item tower 里没有对应信息，内积失去意义）。这是最常见的实现
> 错误，测试里专门有一条断言守着它。

### 5.2 召回实测（`scripts/04_recall.py`）

| 指标 | 实测 | 门槛 |
|---|---|---|
| Recall@50（train） | 0.3930 | — |
| Recall@50（valid） | 0.3575 | — |
| **Recall@50（test）** | **0.3454** | > popularity + 0.01 |
| 热度基线 | 0.3336 | — |
| 随机基线（400 素材取 50）| 0.1250 | — |
| 跨域列泄漏 | **0** | = 0 |
| user / item tower L2 范数误差 | **1.19e-07** | ≤ 1e-4 |

> ⚠️ **这是全项目最弱的一环，如实报出。** test 上 0.3454 只比热度基线 0.3336
> 高 **1.2 个百分点**，勉强过门槛（0.3454 > 0.3436）。原因很直接：mini 档只有
> 400 个素材、候选集太小，而热度基线本身就能拿到 33%。**这一个数字不能用来
> 证明双塔有效**；能把召回和排序两层的口径分开、并守住「跨域特征不进 tower」
> 这条结构约束，才是这一步的价值。full 档（2000 素材）下这个差距会显著拉开。

### 5.3 排序模型消融（`scripts/03_train_ranker.py`）

**三个变体完全共用一套超参** —— 任何一处不一样，差值就不再只反映模型结构。

| 变体 | CTR AUC | CVR AUC | CTCVR AUC | 训练轮数 |
|---|---|---|---|---|
| LR | 0.8220 | 0.8114 | 0.9184 | 16 |
| FM | 0.8732 | 0.7367 | 0.8866 | 16 |
| **DeepFM** | **0.8893** | **0.7739** | **0.9127** | 12 |

| 断言 | 实测 | 门槛 |
|---|---|---|
| `AUC(DeepFM) − AUC(LR)` | **+0.0673** | > 0.03 ✅ |
| `AUC(DeepFM) − AUC(FM)` | **+0.0161** | > 0.015 ✅ |
| pCTR 的 ECE（DeepFM）| **0.0096** | < 0.02 ✅ |

FM 的 trick（`0.5·((Σe)² − Σe²)`）与朴素双循环的差 < 1e-5，O(B·F·d) 而非双重循环。

### 5.4 类别不平衡：1:5 下采样 + 先验校正

下采样把正率从 **0.0487** 抬到 **0.1667**，训练行 **80,388** 行。
模型学到的是**采样后**的先验，推理时必须还原：

```
logit += ln(β),    β = 负样本保留率 = 0.2559  →  logit += −1.3629
```

| | 未校正 | 校正后 |
|---|---|---|
| pCTR 均值 | 0.1392 | **0.0471** |
| 实际 CTR | 0.0500 | 0.0500 |

**漏掉这一步 eCPM 会高估约 3 倍**，而且**不报任何错** —— 只是预算悄悄花飞。

> **SMOTE 的取舍**：1:5 下采样后正率已达 16.7%，SMOTE 功能上冗余。完整实现
> 保留为**消融对照**（实测把正率从 0.1663 抬到 0.2852，生成 9,977 条合成样本），
> 主路径仍是「下采样 + 先验校正 + ESMM」。
> ⚠️ SMOTE **绝不能跨时间切分做** —— 会造出未来样本的近邻，造成时序泄漏。
> 实现上只在 train 折内、固定种子。

### 5.5 延迟反馈去偏：Chapelle DFM

线上拿到的是 24h 窗口 + 末尾截断的标签（实测基率 **0.002259**），
比 168h 回补的 **0.002956** 低 **23.6%**。DFM 用一个额外的标量延迟率头 `λ_d`：

```
L_DFM = −y·log[p(1−e^{−λ_d·e})] − (1−y)·log[(1−p) + p·e^{−λ_d·e}]
```

**受控对照：只有损失函数不同**（vanilla 是同一个架构，只是 `elapsed_h` 恒为 0）：

| 模型 | p̂ 均值 | 对 168h 回补的偏差 | AUC |
|---|---|---|---|
| vanilla（elapsed 恒 0） | 0.001757 | **−40.6%** | 0.9090 |
| elapsed-as-feature（廉价版） | 0.029199 | **+887.8%** ⚠️ | 0.9116 |
| **DFM（本方案）** | **0.002217** | **−25.0%** | **0.9175** |

DFM 把偏差从 **−40.6% 压到 −25.0%**（改善 **38%**），而且 AUC 还略高 ——
**去偏不是靠牺牲排序换来的**。

> ⚠️ **`elapsed-as-feature` 那 +887.8% 不是笔误，是外推爆炸。** 训练折的
> `elapsed_h` 落在 **[121, 168]h**，评测折落在 **[1, 120]h** —— **零重叠**，
> 评测集 **100%** 的行落在训练时从未见过的区间里。`elapsed` 在训练窗口内与
> `day` 高度共线，模型把「日级市场漂移」学成了「elapsed 效应」，外推出去就爆了。
> 这正是「加一列特征」和「建一个延迟模型」的区别。
>
> ⚠️ DFM 必须**关掉早停**：早停判据是「对 `y_conv` 的 AUC」，那是个**排序**指标，
> 而去偏要修的是概率的**水平**，两者不同步。实测开着早停时 DFM 在第 4 个 epoch
> 就被掐掉（偏差 −26.5%），而 vanilla 一路训到第 6 个（−33.5%）—— 比出来只有
> 21% 的改善，看着像「DFM 没用」，其实是**训练被截断了**。固定跑满 12 epoch（
> 指标 json 里的 `dfm_epochs`）后才是 −25.0% 对 −40.6%。

### 5.6 ZILN：零膨胀对数正态金额模型（`scripts/05_ziln.py`）

混合 NLL 自然分解成两项：

```
L_ZILN = BCE(p, 1{y>0})  +  (1/Σ1{y>0}) Σ_{y>0} [ ln y + ln σ + ½ln2π + (ln y − μ)²/(2σ²) ]
```

**期望必须带 `exp(σ²/2)` 修正**：`Ê[y] = p̂ · exp(μ̂ + σ̂²/2)`，不是 `p̂·exp(μ̂)`。
写错会让 eCPM **系统性低估**，而 AUC / Gini **完全看不出来**（它们只看次序不看水平）。

| 指标 | 实测 | 门槛 |
|---|---|---|
| 付费分类 AUC | **0.6332** | > 0.55 |
| └ 理论上限（拿真实付费概率排序）| 0.7543 | — |
| └ 达到上限的比例 | **84%** | — |
| Normalized Gini（按 Ê[y] 排序）| **0.9127** | > 0.30 |
| log-MAE skill | **0.3678** | > 0.10 |
| **聚合偏差**（含 `exp(σ²/2)`）| **0.2784** | < 0.50 |
| 聚合偏差（**漏掉** `exp(σ²/2)`）| **0.5587** | — |
| 纯抽样噪声地板 | 0.1605 | — |

**漏掉 `exp(σ²/2)` 让偏差从 0.2784 涨到 0.5587（放大 2.01 倍）** ——
这就是 eCPM 会低估的比例。

**PIT 必须做两次**（同一个统计量 `Φ((ln y − μ)/σ)`，喂不同参数回答两个问题）：

| 用谁的参数 | 回答的问题 | 实测 p | 结论 |
|---|---|---|---|
| 生成器的**真实** μ、σ | 金额是不是真的对数正态（**建模前提**） | **0.5499** | 前提成立 ✅ |
| 模型的 μ̂、σ̂ | 参数估得准不准（**校准程度**） | **0.0059** | 估得不够准 ⚠️ |

> ⚠️ 只做第二个会看到 p=0.0059，然后得出「对数正态假设不成立、ZILN 从根上就是
> 错的」—— 而真相只是 **σ̂ 估小了**。
> **门槛只压在第一个上**；第二个如实报出，并额外卡一条「σ̂/真实σ ∈ [0.4, 2.0]」
> 防止 σ 头退化。σ 是活的（std 0.1639，范围 [0.327, 1.302]），不是常数。
>
> ⚠️ 这个「σ̂」有**两个口径**，写文档时差点把两个数配成一对：σ 是 `y>0`
> 那一支的尺度参数，而付费用户只有 10%，所以
> **付费样本口径 σ̂ = 0.5405**（真实 0.70，比值 **0.772** ← 该跟真实 σ 比的是这个），
> **全体验证样本口径 σ̂ = 0.4964**（含 90% 的 `y=0`，比值 0.709，但拿它比没有意义）。
> 一度把 0.4964 和 0.772 并排写进 json 与本文档 —— 0.4964/0.70 = 0.709，
> **数字自相矛盾**；`fig07` 照着画也错了（柱子画 0.4964、标注写「0.77 倍」）。
> 现在两个口径在 json 里分别叫 `mean_pos` / `mean_all`，图只画能跟真实 σ 比的那个。

## 6. 职责点 3 —— 智能出价与水位控制

### 6.1 优化问题与三环分工

```
max  Σ q_i · P(win | b_i)      s.t.   Σ c_i · P(win | b_i) ≤ B
```

λ 是**预算的影子价格**，最优出价 `b* = v/λ`，`α = 1/λ` 就是**出价水位**。

**对偶梯度（符号极易写反）**：`λ ← λ + η_λ·(S(λ) − B)`。
在 log 空间更新 `ln α` 天然保证恒正。**单步自检**（实测）：

| 情形 | α 变化 | 方向正确 |
|---|---|---|
| 超支 | 1.0000 → **0.9470** | ✅ 超支压低水位 |
| 不足 | 1.0000 → **1.0056** | ✅ 不足抬高水位 |

**三环分工 —— 这是「PID 到底控制什么」的答案**：

| 环 | 时间尺度 | 职责 |
|---|---|---|
| **前馈 λ** | 每小时 | 「每份预算的经济价值是多少、该出多高价」→ 决定**买什么**，慢、平滑、有经济含义 |
| **反馈 PID** | 每 15min slot | 「预测错了怎么临时调整才能按进度花完」→ 只管**花多少**，快、有界 |
| **硬闸门** | 每请求 | 保证**绝不超支**这条红线 |

PID 递推：`e_t = (B·F(t) − A_t)/B`，`u_t = clip(K_p·e + I_t + K_d·Δe, ±u_max)`。
`F(t)` 用**历史流量曲线归一化**得到，**不是线性** `t/T`（线性会让 PID 在流量低谷疯狂提价）。

|---|---|

### 6.4 预注册的恒等性：整体缩放价值对按比例出价的买手是不是恒等

**推导**（写在代码 docstring 里，**先于测量**）：`build_policies` 用 `solve_alpha`
反解水位 α 使 `E[spend(α·v)] = plan/n`。若把 v 整体乘 c，则 α 精确缩到 α/c，
于是逐请求出价 `(c·v)·(α/c) = v·α` **完全不变** —— 恒等。

四个判据的实测：

| 判据 | 实测 | 结论 |
|---|---|---|
| ① 水位之比 `α_raw/α_lvl` | 2.6130 / c = 2.6303，差 **0.657%** | `solve_alpha` 的协变性成立 ✅ |
| ② 水位是否触边界 | 未校准**没触**，校准后**没触**（带 [0.05, 5.00]）| 无饱和 ✅ |
| ③ 硬闸门命中次数 | 未校准 **3**，校准后 **3** | 闸门触发了 |
| ④ B4 价值 | 1521.6 → **1639.9**（**+7.772%**），校准侧占优 | 与预注册方向一致 ✅ |

> **这是整条链路里唯一不和缩放交换的部件。** 硬闸门把一批的**期望**扣费压在
> 剩余预算内，而期望扣费对出价**超线性** —— 出价虚高 c 倍，闸门压得比 1/c 更狠。
> 所以校准侧反而更优，**差值 7.772% 就是闸门的代价**。
>
> **如果没有闸门（纯比例出价 + 外生预算），校准前后会逐位相同。**
> 结论：**水平校准的价值全在闸门和对外可解释性上（水位数值、风控阈值、
> 跨渠道比价），不在排序上。**

### 6.5 预算必须外生 —— 一个真实的返工

第一版用 `budget = u_pred / 3.6` 反解预算。这**看起来更"公平"**（预算跟着模型走），
实际是错的：校准改变了模型水平 → 改变了预测花费 → 改变了预算。
「校准让价值涨了」里混着「预算也涨了」，**两件事分不开**，
而且小预算会把 B5 的 α* 顶到 `alpha_min` 下界，把上帝视角裁掉一刀。

改成由 `stream.true_value_cpm`（**真实**价值）反解，三次仿真**共用同一个预算**
（**50 元**，tension 3.6，`budget_source` 字段记的就是这件事）：

| | esmm_raw | esmm_level | dfm_raw |
|---|---|---|---|
| B0 期望价值 | 184.755044 | 184.755044 | 184.755044 |
| B5 期望价值 | 6091.978312 | 6091.978312 | 6091.978312 |

**逐位相同。** 这证明了预算确实外生（预算由广告主设定，不由模型决定），
也顺带证明了三次仿真抽到的是**同一条请求序列** —— 这是配对比较，
策略间的差异里不会混进流量抽样噪声。

### 6.6 两个 q 的构造方式 —— 一次真实的模型选择

| 变体 | `pred_q` | 说明 |
|---|---|---|
| `esmm` | pCTR × pCVR | 线上主路径，ESMM 结构 |
| `dfm` | DFM 直接输出的 P(转化) | 一条链路估到底，跳过相乘 |

| 变体 | B4 相对 B0 | B4 / B5 |
|---|---|---|
| `esmm_raw`（未校准）| +723.6% | 0.2498 |
| `esmm_level`（已校准）| +787.6% | 0.2692 |
| **`dfm_raw`** | **+1423.3%** | **0.4620** |

**换一个 q 的构造方式，买到的东西翻了近一倍。** 这是仿真能回答、
而离线指标（AUC）回答不了的问题。

**⚠️ 「拍卖只在乎排序」这句话说对了一半，但用错了指标。**

| 指标 | esmm | **dfm** | 谁该赢 |
|---|---|---|---|
| 全量 Spearman | **0.4880** | 0.3826 | dfm ← **反向** ❌ |
| 弹性 γ | 0.4834 | **0.7943** | dfm ✅ |
| 截获率（紧预算）| 0.2952 @1.2% | **0.3941 @1.4%** | dfm ✅ |

**全量 Spearman 反向不是噪声，而是它测错了东西**：出价是 `b = α·v`，
**按比例**而不是按名次。把 v 做任何**单调**变换，α 会恰好反向补偿
（判据①证明的就是这件事），逐请求出价一个字都不变 —— 而 Spearman 只排名次，
**对单调变换完全免疫**。它测的正是拍卖**看不见**的那部分。
拿它给「拍卖只在乎排序」作证，会得出**反的**结论。

真正决定买到什么的是预测的**离散程度**：`γ` 是 `log(真值)` 对 `log(预测)` 的
回归斜率。γ = 1 说明预测的高低比例跟真值一致；γ < 1 说明预测**过度发散** ——
头部出价被抬到远超真值的水平，预算全砸在那几个虚高的出价上。
`esmm` 的 v 是**三个各自带噪的概率相乘**，噪声跟着相乘放大，所以 γ 只有 0.48；
`dfm` 一条链路估到底，γ = 0.79。

**截获率**（按预测取前 f，拿到的真值 / 按真值取前 f 本可拿到的）只在**紧预算**下
有效 —— 实测 B4 的 `win_rate` 只有 **1.19%~1.41%**（`buy_frac` 与它同源），
预算只买得起池子里那么一小段，所以这里只在这个 f 上报告截获率。
f 一放宽到百分之几，两个变体就分不开了：那时买的是池子的大半，
按什么排序都能拿到差不多的总量。
**预算越紧，排序越值钱** —— 这本身就是智能出价要解决的问题的另一种说法。

### 6.7 诚实下界：为什么最好也只有 0.46

**B4/B5 最好也只有 0.4620，远低于 06 里纯合成数据的 0.9524。**
差的那部分是**真实模型误差的代价**，不是控制环的问题：B5 用真值出价、排序完美，
B4 用的是预测。**这是排序问题，不是水平问题** —— 任何一个常数都修不了它
（常数的效果被 6.4 的恒等性抵掉了）。

这里如实报出，并把它列为后续工作（重训模型 / 把乘积的排序修好），
**而不是把门槛降到实测值以下来「通过」**。

## 7. 职责点 4 —— 科学实验验证

### 7.1 分流：`blake2b`，不是内置 `hash()`

```python
bucket = int.from_bytes(blake2b(f"{exp_id}|{salt}|{user_id}".encode(), digest_size=8).digest(), "big") % 10000
```

> ⚠️ **绝不能用内置 `hash()`** —— str 的 hash 有 **per-process 随机盐**，
> 重启进程分组就变了，实验作废。
> ⚠️ 不同实验必须用**不同 `exp_id`** 前缀参与哈希。
> ⚠️ `user_id % 2` **不是随机**（真实 user_id 常有奇偶规律）。
> 分流单元 = `user_id`（同一个用户的多次曝光必须落在同一组）。

### 7.2 AA 空跑：断言的是**分布**，不是单次 p 值

**AA 两组跑完全相同的策略，H0 为真，p 值必然服从 U(0,1)。** 所以：

- **无法「保证」单次 AA 的 p > 0.05** —— 它本来就有 5% 的概率失败。那不是 bug，是定义。
- 正确做法：跑多次独立 AA（每次换 `exp_id`），断言 p 值的**分布**。

实测 **60** 次独立 AA：

| 指标 | 实测 | 门槛 |
|---|---|---|
| **KS 均匀性 p 值** | **0.1154** | > 0.05 ✅ |
| **假阳性率** | **3.33%** | ∈ [0.01, 0.12]（理论 0.05）✅ |
| p 值 p10 / 中位数 / p90 | 0.2015 / 0.5593 / 0.8858 | 理论 0.1 / 0.5 / 0.9 |
| SRM 卡方 p 最小值 | 0.0414 | > 0.001 ✅ |

**这比「跑一次看 p>0.05」统计上正确得多。** 单次 AA 的 p>0.05 **不能**当作
「通过」—— 它的假阳性率就是 5%。

### 7.3 样本量：power analysis 真的改变了设计

按 CVR 基线 **0.0609**、MDE 相对 **5%**、α=0.05、power=0.8 反解：

| | 忽略 deff（naive）| 计 deff |
|---|---|---|
| 设计效应 deff | 1.0 | **7.6213** |
| 所需总用户数 | 11,554 | **88,054** |
| 可用用户数 | 100,000 | 100,000 |
| 达成功效 | 1.0000（不现实）| **0.8475** |
| 可用样本下的 MDE | 1.69% | **4.69%** |

**同一个「10 万用户」，忽略 deff 会以为功效 99.99%、能测 1.69% 的微小提升；
修正 deff 之后才知道功效只有 84.75%、最小可测提升是 4.69%。**
deff = 7.62 来自「一个用户有 17.16 次曝光」的簇内相关 —— 用户内的曝光高度同质，
有效样本量远小于名义样本量。**这个反解本身就改变了实验设计**：
如果想测 3% 的提升，10 万用户根本不够。

### 7.4 AB 主实验

| 项 | 实测 |
|---|---|
| 实验 ID | `pacing_v2` |
| SRM 卡方 p | **0.7954**（对照组 50,041 / 实验组 49,959）✅ |
| **主指标 CVR** | 0.05928 → 0.06251，**+5.45%**，**p = 0.00133** ✅ |
| 估计方法 | **Delta method**（比率指标不能用普通 t 检验）|
| 注入的真实提升 | +5.00%，置信区间**覆盖真值** ✅ |
| CUPED | ρ = **0.526**，方差降低 **27.67%**，校正后 p = 0.00110 |
| 日粒度同号比例 | **100%**（跨完整业务周期）|

**次要指标与护栏**（Benjamini–Hochberg 多重比较校正）：

| 指标 | 提升 | p 值 | BH 拒绝 |
|---|---|---|---|
| CTR | −1.73% | 0.0898 | 否 |
| RPM | −5.20% | 0.6819 | 否 |
| ROI | −4.97% | 0.6956 | 否 |
| CPA | −3.73% | 0.0922 | 否 |
| **护栏：零转化率** | **−2.48%** | **1.32e-06** | — |

> ⚠️ **比率指标（CVR / ROI / CPA）的分子分母都是随机变量，不能用普通 t 检验。**
> 这里用 Delta method；边界情形（n<30 或 x<5）退化为 Fisher / 置换检验；
> 零方差返回 NaN 而非抛异常；`p̂` 接近 0/1 用 Wilson 区间。

### 7.5 部分覆盖的偏差诊断

实验只覆盖 **30%** 流量、注入真实提升 **+6%** 时，跑 10 次重复：

| 指标 | 实测 |
|---|---|
| 估计的 ATE 均值 | **0.06716**（真值 0.06）|
| 估计的标准误 | 0.00316 |
| 估计的 SD | 0.01000 |
| **比值（估计/真值）** | **1.1194** |

**部分覆盖会让估计值偏高约 12%** —— 因为被覆盖的那部分流量不是随机的，
而是与效果异质的那部分人群相关。这个偏差**不会随样本量增大而消失**，
只能靠扩大覆盖或做加权修正来解决。

## 9. SparkSQL ↔ pandas 映射

`sql/` 下是**生产环境的 SparkSQL 脚本**（本项目不执行它们 —— 决策是只提供脚本 +
pandas 等价实现，不引入 pyspark）。`src/features/pipeline.py` 是与之一一对应的
pandas 实现，两者产出**同一份列定义**。

| SparkSQL 做法 | pandas 等价实现 | 说明 |
|---|---|---|
| `SELECT ... FROM user_profile` 宽表 | `build_user_profile()` | 192 列，含 60 噪声 + 26 冗余 |
| `GROUP BY user_id` + `count/sum/avg` | `groupby().agg()` | 30 个行为特征 + 30 个统计聚合 |
| `datediff` / `window` 滑窗 | `rolling` + 时间索引 | 近 7/14/30 日窗口 |
| `JOIN item_meta ON item_id` | `merge(on="item_id")` | 素材侧 7 类别域 + 4 数值 |
| `CASE WHEN is_convert=1 AND delay_hours<=24 THEN 1 ELSE 0 END` | 布尔掩码赋值 | **双窗口标签回补（核心）** |
| `COUNT(DISTINCT ...)` | `nunique()` | 类目去重 |
| `percentile_approx(col, 0.5)` | `quantile(0.5)` | 延迟分位数 |
| `StandardScaler` → `PCA` | `sklearn.PCA` | **必须先标准化** |
| `KMeans(k, init='kmeans++')` | `sklearn.KMeans(n_init=…)` | **在 PCA 空间做** |

**标签回补是这一步的核心**，对应 `sql/03_sample_join.sql`（下面是**原文节选**，
不是示意写法 —— 示意写法容易和真跑的 SQL 悄悄分家）：

```sql
-- 线上真实标签：24h 窗口 + 数据末尾截断
CASE WHEN e.is_convert = 1 AND e.delay_hours <= 24  THEN 1 ELSE 0 END AS y_conv_w24,
CASE WHEN e.is_convert = 1 AND e.delay_hours <= 168 THEN 1 ELSE 0 END AS y_conv_w168,

-- 观测时长：从曝光到数据拉取时刻。末尾 7 天的曝光等不满 168 小时。
-- ⚠️ 这一列是延迟反馈模型（DFM）的关键输入。
--    如果它退化成一个常数，DFM 的修正项就完全没有区分度，
--    而训练照样收敛、指标照样出 —— 属于最危险的那类静默错误。
LEAST(168.0,
      (unix_timestamp(current_timestamp()) - unix_timestamp(e.event_time)) / 3600.0
) AS elapsed_h
```

> `y_conv_w24` 是线上真实可得的**有偏**标签（实测假负 **24.5%**），
> `y_conv_w168` 是回补参照（假负只剩 **2.8%**）。
> ⚠️ `label_oracle`（无限窗口真值）**只存在于模拟里，线上永远拿不到，绝不进训练**。
> `elapsed_h` 那一列看着无害，但它是 `elapsed-as-feature` 外推爆炸（§5.5）
> 和 DFM 用来去偏的**同一个**输入 —— 区别只在怎么用它。

## 10. 主要踩坑清单

这些都是**实际踩到并修掉**的，不是预防性清单。

### PyTorch

- `nn.Embedding` 输入必须 `long` 且索引不越界 —— 越界**不报错**，返回垃圾值。
- 本机 `torch.use_deterministic_algorithms(True)` 在 CPU + Embedding 反向会抛错，保持 `False`。
- Windows 上 `DataLoader(num_workers>0)` 会 spawn 死循环 → 用 `0`。
- 忘写 `model.eval()` 是「结果不稳定」的头号原因。
- `AdamW` 的 `weight_decay` 别加到 embedding 和 bias 上。
- **测试里必须 `torch.set_num_threads(1)`** —— 多线程会让 `nn.Linear` 的归约顺序
  非确定，loss 从小数第 6 位漂移，任何精确断言都会变成随机失败。

### 数值

- FM 的 `sum_sq ≥ sq_sum` 逐元素成立，但浮点可能微负 —— **不要开根号**。
- `sigmoid` + `log` 用 `logsigmoid`，别自己拼。
- **`pos_weight`（训练技巧）与先验校正（推理还原）是两件事**，混起来会把概率修两遍。
- DFM 里 `(λ_d·e)` 必须 `clamp(max=30)` 防 exp 溢出，`p_pos` 必须 `clamp_min(1e-7)` 防 `log(0)`→NaN。
- ZILN 的 batch 内可能无正样本，必须 `if n_pos == 0` 保护，否则训练中途 NaN。
- `Ê[y] = p̂·exp(μ̂ + σ̂²/2)`，**不是** `p̂·exp(μ̂)`。

### 统计

- **比率指标（CVR/ROI）用 t 检验是错的** —— 分子分母都是随机变量。
- **绝不能中途反复 peek 再决定何时停** —— type-I 错误率会从 5% 飙到 20%+。
- **单次 AA 的 p > 0.05 不是「通过」**，要断言分布。
- **SRM 是最灵敏的 bug 探测器** —— 分流写错、日志丢一边，主指标可能仍然「显著」。

### 工程

- 路径含空格（`D:\advertising recommending system`）→ **全程 `pathlib.Path`**，
  subprocess 用 **list 形式**，不要 `shell=True` + 字符串拼接。
- 无 pyarrow → 不能存 parquet → 用 **pickle + float32**（192 列 × 300 万行，
  float64 是 5.2GB、float32 是 2.6GB）。
- **C 盘只剩 0.6GB** → 所有产物落 D 盘；pip 装包必须重定向
  `TEMP`/`TMP`/`TMPDIR` 和 `--cache-dir` 到 D 盘。
- matplotlib 后端在本机是 `tkagg` → 存图前**强制 `Agg`**，否则 CI / 后台会崩。
- **「数出来的数」要数对对象**：统计特征宽度时数了 `DataFrame.columns` 而不是
  声明的特征列，于是 13 个 `_true_*` 隐变量列被算成了「特征」，
  报出 209 列（真值 192），噪声占比也被摊薄成 41.1%（真值 44.8%）。
  症状是那行日志的右边加起来对不上左边。**这类错误不会让任何测试失败** ——
  它只是把数字说大了一点，而数字正好会被抄进 README。详见 §4.2。
- **同一个名字的两套口径，绝不能并排存** —— 本项目的第三次栽跟头。
  前两次是「曝光级 vs 点击级」（§4.1）和上面的 209/192；第三次是 ZILN 的 σ̂：
  `sigma.mean`（全体，含 90% 的 `y=0`）和 `sigma.ratio_to_true`（只有付费样本）
  被当成一对存进 json，于是 `0.4964 / 0.70 = 0.709` 与写着的 `0.772` 对不上 ——
  **文件自己跟自己矛盾**，`fig07` 照着画也错了（柱子画 0.4964、标注写「0.77 倍」）。
  现在两个口径分别叫 `mean_pos` / `mean_all`，**键名自带口径**。
- 因此新增 `tests/test_readme_numbers.py`：把「本文档每个数字都能在
  `artifacts/metrics/*.json` 里找到」变成一条**会失败的断言**。
  上面三条错的共同点是 —— 全都**不会让任何测试变红**，只是安静地写进文档。
  这个文件就是专门补这一层的（σ 口径那条还单独设了回归守卫）。

### Windows 控制台编码（一类**静默**故障）

Windows 上 Python 的 stdout 默认是 **GBK（cp936）**，于是：

| 写法 | 后果 |
|---|---|
| `print("σ²/2")` | **抛** `UnicodeEncodeError`，报错位置不在编码而在调用处 |
| `log.info("σ²/2")` | **不抛**。`logging.StreamHandler.emit` 捕获异常、往 stderr 打一行 `--- Logging error ---`，然后把**整行日志丢掉**，脚本照常跑到「体检通过」 |
| 任何中文输出 | 终端里变成乱码 |

**实测 GBK 编不出来的字符**：`² Ê ̂ −(U+2212) ⇒ ⚠ ✅ ❌`，以及变体选择符 U+FE0F ——
而这些都是本项目注释和输出里天天用的符号。

**修法**（`scripts/_common.py`）：在创建 logger **之前**把 `sys.stdout/stderr`
`reconfigure(encoding="utf-8")`，一次解决三件事。`-I` 隐含 `-E`，
所以 `PYTHONIOENCODING` 环境变量**不生效**，必须走 `reconfigure`。

> 另有 matplotlib 的同类问题：中文字体缺失时**不报错**，只把字画成方框。
> 而且 `p̂` / `σ̂` 里的**组合抑扬符 U+0302** 微软雅黑没有 —— 图上会是个豆腐块。
> 所以图上的文字一律避开组合字符与 emoji。

### 出图

- `fig.tight_layout(rect=...)` 只保证**轴**之间不重叠，**管不到标题**。
  两行的子图标题能顶到 `y=0.99`，正好撞上默认 `y=0.98` 的 `suptitle` ——
  屏幕上就是两段文字叠印。要自己留白。
- `01_data` 的假负表最后一行的 `window_h` 是字符串 `"online"`（代表线上那份
  带截断的标签），直接丢进对数 x 轴会在 `set_xticks` 里抛
  `'<' not supported between 'str' and 'int'` —— 因为 `min()` 要排序。

> ⚠️ 机器上其实**有**一块 RTX 3050 Laptop，但装的 torch 是 **CPU 版**
> （`2.6.0+cpu`，`torch.cuda.is_available()` 为 `False`，`torch.version.cuda`
> 为 `None`）—— 所以本文档里的每个数字都是纯 CPU 跑出来的。
> 要复现的话装 **CPU wheel** 即可，不必装 CUDA 版，也不必准备显卡：
> 全链路的规模是刻意压到单机 CPU 能几分钟内跑完的量级。

**本设计不需要任何新增第三方依赖**（见 `requirements.txt`）：

- SMOTE **自实现**（`src/models/sampling.py`），不需要 `imblearn`；
- 统计检验全走 `scipy.stats`，不需要 `statsmodels`。实际用到的就这五个：
  `norm.sf` / `norm.ppf`（Z 检验与功效反解）、`norm.cdf`（对数正态拍卖的
  `P(win|b)` 与 PIT）、`chi2.sf`（**SRM** 卡方）、`fisher_exact`（小样本退化路径）、
  `kstest`（AA 空跑的 p 值均匀性、ZILN 的 PIT）。
  ⚠️ **没有 `ttest_ind`** —— 主指标是比率（CVR），用 Delta method 自己算方差，
  普通 t 检验在这里是错的（见 §7.4）；
- 不存 parquet，不需要 `pyarrow`；
- pyspark 按决策不装。

测试写成**普通 `assert` + `test_*.py` 命名**，所以 `pytest` 和自带的
`run_tests.py` **两种方式都能跑**，且结果一致。
